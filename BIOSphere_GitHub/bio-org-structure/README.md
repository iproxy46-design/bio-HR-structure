# БИОсфера — оргструктура и сотрудники

Приложение работает на Next.js (Node.js) и PostgreSQL. Основное хранилище —
таблицы `units`, `employees`, `employee_photos`, `org_revision`, `login_attempts`.
Карточки и структура сохраняются непосредственно в PostgreSQL.
Кнопки Excel убраны из редактора. Фотографии хранятся в PostgreSQL как `bytea`.

## Локальный запуск

Требуются Node.js 22.13+ и PostgreSQL. Настройки в игнорируемом `.dev.vars`:

```dotenv
DATABASE_URL="postgresql://USER:PASSWORD@127.0.0.1:55432/bio_org"
ADMIN_USERNAME="admin"
ADMIN_PASSWORD="your-password"
ADMIN_SESSION_KEY="a-long-random-session-secret"
```

Существующий `ADMIN_PASSWORD_RECORD` имеет приоритет над `ADMIN_PASSWORD`.
Значения конфигурации не выводятся в лог. Не добавляйте `.dev.vars` в Git.

```sh
corepack pnpm install --frozen-lockfile
npm run build
npm start
```

Адрес: `http://127.0.0.1:8787/`. Для разработки — `npm run dev`.
Для другого порта задайте `PORT`; для доступа из локальной сети — `HOST=0.0.0.0`.
`scripts/run-node.mjs` загружает окружение и создаёт отсутствующие таблицы из
`db/postgres.sql`. Пустая база открывает пустой редактор: администратор создаёт
первую независимую структуру. Реальные данные не включаются в клиентский код.

При установленном PostgreSQL можно создать отдельный локальный экземпляр:

```powershell
$env:PG_BIN = 'C:\path\to\postgresql\bin'
node scripts/setup-local-postgres.mjs
```

Он использует порт 55432 и каталог `.sites-runtime/postgres`, не затрагивая
другие экземпляры. Повторный запуск проверяет существующий экземпляр.
Каталог `.sites-runtime` содержит базу и локальные секреты и исключён из Git/Docker.

## Перенос из старой версии

Сначала при работающей старой версии сделайте резервную копию:

```sh
node scripts/export-legacy.mjs http://127.0.0.1:8787 .sites-runtime/legacy-backup.json
```

Скрипт сохраняет структуру, сотрудников и фотографии, выводит только количества.
Существующий файл не перезаписывается. На время перехода прекратите редактирование
старой версии. После настройки `DATABASE_URL` для пустой PostgreSQL-базы:

```sh
node scripts/migrate-postgres.mjs .sites-runtime/legacy-backup.json
```

Миграция отказывается перезаписывать непустую базу и автоматически сверяет все поля
и байты фотографий, не выводя их. Старые D1/R2 и резервная копия сохраняются.
После успешной проверки остановите старую версию и запустите `npm start`.
Не запускайте старые vinext/Cloudflare-команды для новой версии.

## Редактор

Вход администратора → «Редактировать» → «Структура компании»:

- «Новая структура» создаёт независимую компанию, филиал или направление.
- Нажатие названия открывает переименование, перенос и выбор руководителя.
- «Внутри» добавляет дочернее подразделение.
- «Разделить» создаёт подразделение и переносит выбранных сотрудников и команды.
- «Удалить» запрашивает подтверждение; для непустого подразделения требуется
  выбрать другое место для сотрудников и дочерних команд. Люди не удаляются.

Число корневых структур и глубина дерева не привязаны к исходным ID. Нельзя
перенести подразделение внутрь собственной ветки. Руководитель определяется по
ближайшему подразделению вверх по дереву. Несогласованные старые назначения не
перекрывают эту иерархию. Ссылка на руководителя открывает его карточку.
Местонахождение можно ввести произвольно.

Сохранение выполняется транзакцией с блокировкой версии; устаревший редактор получает
HTTP 409 вместо перезаписи чужих изменений. Ограничения формы: 500 подразделений,
2000 сотрудников. Правки данных доступны только администратору с проверкой Origin.

## Docker / сервер

В `.env` задайте случайный `POSTGRES_PASSWORD` (hex-строка), в `.dev.vars` — параметры
администратора. Docker Compose передаёт собственный `DATABASE_URL` поверх локального.

```sh
docker compose config --quiet
docker compose up --build -d
```

PostgreSQL не публикуется в сеть. Данные сохраняются в томе `postgres-data`.
Приложение доступно на порту 8787; миграция серверных данных выполняется отдельно.
Не используйте `docker compose down -v`, если нужно сохранить базу.

### Обновление заполненного сервера

Если сервер уже использует PostgreSQL, оставьте прежние `.env`, `.dev.vars`,
каталог проекта и том базы. Выполните резервное копирование (см. ниже), затем
`docker compose up --build -d`. Повторный запуск создаёт только отсутствующие
таблицы: он не очищает записи и не загружает исходный Excel заново.
Имя Compose-проекта определяет имя тома; при смене каталога/имени проекта
необходимо явно подключить прежний том, иначе будет создана отдельная пустая база.

Если на сервере ещё старая версия с D1/R2, **до остановки старого приложения**
выполните экспорт из раздела «Перенос из старой версии». Используйте именно
серверный экспорт, чтобы сохранить последние серверные правки. Он содержит
сотрудников, структуру, контакты и фотографии — повторный импорт Excel не нужен.
Сохраните также прежний каталог данных D1/R2. Затем:

```sh
docker compose build web
docker compose up -d postgres
docker compose run --rm --no-deps -v "$(pwd)/.sites-runtime:/migration:ro" web \
  node scripts/migrate-postgres.mjs /migration/legacy-backup.json
```

Продолжайте только после сообщения `Migration verified`. Миграция сверяет все
поля и фотографии и отказывается перезаписывать непустую PostgreSQL-базу.
После проверки остановите старое приложение и выполните
`docker compose up -d web`. Старое хранилище и файл экспорта не удаляются.
Не переносите локальную тестовую базу поверх существующей серверной.

Для `http://bioorgstructure/` создайте внутреннюю DNS-запись
`bioorgstructure → 172.31.16.4`, освободите порт 80 и запустите:

```sh
docker compose -f compose.yaml -f compose.bioorgstructure.yaml up --build -d
```

## Резервное копирование PostgreSQL

Локально: `node scripts/backup-postgres.mjs`. Каталог `pg_dump` задаётся через
`PG_BIN`, если его нет в PATH. Дамп сохраняется в `.sites-runtime/backups`;
содержимое базы не выводится в консоль.

```sh
docker compose exec -T postgres pg_dump -U bioapp -d bio_org -Fc > bio-org.dump
```

Сохраняйте `.dev.vars` и `.env` отдельно в защищённом месте. Восстанавливайте дамп
в отдельную пустую базу через `pg_restore`, затем переключайте `DATABASE_URL`.
Старая резервная копия D1 не является резервной копией PostgreSQL.

## Проверки

```sh
node scripts/test-org-display.cjs
node scripts/test-employees-excel.cjs
node --import tsx scripts/test-postgres.ts
node scripts/test-org-ui.cjs
```

PostgreSQL-тест создаёт отдельную временную схему, проверяет API и удаляет только её.
UI-тест использует вымышленные записи и изолированный HTTP-сервер; нужен
`playwright-core` (путь можно задать через `PLAYWRIGHT_MODULE`) и установленный Edge
либо `BROWSER_CHANNEL`. Проверяются три ширины: 1440, 768 и 390 px.

Основа транзакций: [node-postgres](https://node-postgres.com/features/transactions).
Управление локальным экземпляром: [PostgreSQL pg_ctl](https://www.postgresql.org/docs/current/app-pg-ctl.html).
